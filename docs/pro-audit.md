# Pro 觀眾流程與修正紀錄

範圍：獨立 `/pro/` 頁面。原首頁的 HTML、CSS、JavaScript 保持不變。

## 逐一檢視 user stories

### 1. 第一次進來，我想知道這跟我的生活有什麼關係

- 觀眾語言：「我已經不用寫作業了，為什麼要看？」
- 畫面：從等家人用完電腦的日常出發，說明接下來會看三組台灣資料。
- 操作：按「開始看展」，或直接選電腦與網路、教育開銷、課後照顧。
- 得到：知道展覽關注完成作業前的支持，並能選擇閱讀入口。

### 2. 我想隨時知道自己在哪，也能直接前往另一個主題

- 畫面：導覽列固定在畫面上方，展覽內容在下方獨立捲動。進度與目前章節會更新。
- 操作：點章節、用手機選單、按回到頂端，或開啟帶有章節 hash 的網址。
- 得到：導覽不被捲走，內容不被導覽遮住。每章尾端也提供下一步。
- 檢查：桌面 header 底部與 scrollport 頂部同為 76px，手機同為 68px。根文件 scrollY 維持 0。

### 3. 我想知道「能上網」和「有電腦」有什麼差別

- 畫面：題目「家裡能上網，就能好好寫作業嗎？」預設顯示「家裡能上網」。
- 操作：先讀 84.82% 與 96.09%，再按「家裡有電腦」。
- 得到：數字變成 27.82% 與 66.96%，解釋同步更新。收入最低兩成家庭中，每 100 戶約 85 戶能上網，約 28 戶有電腦。
- 限制：這是家庭是否有設備，不能得知某位孩子能否使用，也不能證明作業表現或因果。全體平均包含最低收入組。
- 檢查：滑鼠與 Enter 皆可切換，選取狀態、文字、長條與輔助科技通知同步。

### 4. 我想看懂教育開銷，而不是被幾個大數字說服

- 畫面：明寫「每戶一整年的平均教育支出」、2024 年、新台幣。收入組別使用一般說法。
- 操作：選擇孩子人數、求學階段或支出是否足夠的問題。
- 得到：看到每個問題對應的解釋，了解平均每戶支出不能直接換成每位孩子的資源。
- 限制：只呈現部分組別及全體平均，完整表格可從來源區開啟。

### 5. 我想知道學校能提供多少課後支持

- 畫面：100 格中填滿 72 格，附圖例、開辦校數、總校數與學年。
- 操作：展開「有開辦，就代表每個孩子都能參加嗎？」。
- 得到：分清學校開辦比例與學生參與比例，知道名額、時間、費用仍需要了解。
- 限制：每格約 1%，不是一所學校。不能從這個比例推論不同收入學生的使用情況。

### 6. 看完以後，我想帶走一個能用在生活中的想法

- 畫面：「再努力一點」之前，也可以先問「你需要什麼幫忙？」。
- 得到：把注意力從個人努力延伸到設備、預算和陪伴，連回教育公平。
- 限制：單一年份不能回答差距是否正在擴大。頁面直接說明這個缺口，不加入尚未確認的 SDG 細項。

### 7. 我想查證數字

- 操作：從每張圖的來源連結展開對應資料，再開啟官方報告。
- 得到：家庭設備指向第 10 表、PDF 第 110 頁，教育支出指向第 6 表續表、PDF 第 88 頁。學校資料指向「兒童課後照顧服務班概況」。
- 檢查：來源 details 深連結可直接展開，內文同時列 PDF 頁碼與書面頁碼。

### 8. 我想留下想法，也想知道送出進度

- 畫面：整體感受評分、想回應的主題、兩個選填文字欄位。不收姓名或聯絡方式。
- 操作：選評分與主題後送出，可看到字數、送出中、送出結果與連線失敗提示。
- 得到：不強迫觀眾表示受啟發或選最喜歡的主題。送出時鎖定重複操作，失敗保留內容。
- 檢查：只操作必填驗證與填寫後清空的字數計數，沒有新增測試回饋列。使用者已確認既有回饋會寫入試算表，本次不更換端點或後端。
- 限制：瀏覽器無法讀取 Apps Script opaque 回應，畫面只說「已送出」，不宣稱已驗證寫入。25 秒逾時不自動重送。

### 9. 我使用手機或鍵盤，也想完成一樣的流程

- 畫面：手機單欄、可展開導覽、44px 以上主要觸控目標、表單字級 16px。
- 操作：鍵盤選設備、展開來源、填表。Escape 關閉手機選單並回到選單按鈕。
- 得到：焦點可見，純 icon 按鈕有名稱。減少動態效果時關閉入場動畫與平滑捲動。
- 檢查：320px、390px 與桌面版面。Noto Sans TC 套用到標題、數字、表單與內嵌 SVG 文字。

## 原問題逐項處理

| 問題 | 本次狀態 |
| --- | --- |
| 文案像開發規格，觀眾不知道為什麼要看 | 日常入口、各章問題與操作後解釋 |
| 標題問上網，預設卻顯示電腦 | 預設上網，清楚引導再看電腦 |
| 缺少下一步，互動目的不清楚 | 三章分別提供比較、提問與資料限制，章尾加入下一步 |
| 分號、破折號、英文裝飾與開發者詞彙 | 展覽可見文案不使用分號、破折號或技術狀態說明 |
| 單年資料被理解成差距擴大 | 結尾明示尚不能判斷趨勢 |
| 家戶支出、學生人數與學校比例混用 | 年度、單位、分母與不能推論的範圍分別說明 |
| 日期與收入分組難懂 | 使用 2024 年及「2024 年開始的學年（113 學年度）」與一般語句 |
| 來源沒有精確定位 | 官方資料名稱、表號、PDF 頁碼與連結 |
| Navbar 包含在文件 scrollbar 中 | header 與 exhibition-scroll 為同層獨立區塊 |
| Scrollbar、gutter 與左右不置中 | 區域捲軸樣式、穩定 gutter、左 padding 補償與 header 兩側對齊 |
| 顏色太多、底色不白 | 純白底，三個藍色加黑白，移除原綠、橘與米色 |
| 字體混用、數字襯線 | 全部 Noto Sans TC |
| 手刻所有版面與元件 | Tailwind CSS CDN 負責響應式、字級、間距與共用元件，僅保留捲動和圖形特殊 CSS |
| 小字、窄螢幕與觸控問題 | 主要文字 16px、輔助文字 14px、主要按鈕至少 44px，窄螢幕設備按鈕隱藏裝飾 icon |
| Icon 混雜、可辨識操作仍有冗詞 | Lucide CDN，來源、選單、回頂使用純 icon 及 aria-label/title |
| 評分預設正面、主題強迫選最有感 | 改為整體感受及「你想回應哪個主題？」 |
| 送出重複、按鈕縮小與送出後跳動 | 保留提交鎖、固定最小按鈕寬度與回饋區最小高度 |
| 回饋連線狀態不清楚 | 傳送、錯誤、逾時及成功文案，保留內容，不自動重送 |
| 隱私與字數提示 | 不收個資、兩個 1500 字上限與即時字數 |
| 鍵盤與 reduced motion | 焦點樣式、選單 Escape、無障礙名稱及 GSAP 媒體條件 |

## 視覺與技術選擇

- [Color Hunt 原配色](https://colorhunt.co/palette/0c2b4e1a3d641d546cf4f4f4)：採用 `#0C2B4E`、`#1A3D64`、`#1D546C`，底色換成 `#FFFFFF`，文字搭配 `#000000`。僅中性邊線及裝飾使用透明度。
- [Tailwind Play CDN 官方文件](https://tailwindcss.com/docs/installation/play-cdn)：依使用者要求使用 CDN，固定 4.3.0 與 SRI。官方定位為開發用途，現階段 Pro 依賴瀏覽器即時產生樣式與 CDN 可用性。若之後要改善正式載入效能，下一步可將同一套 utilities 改為建置輸出，不需要重做設計。
- `src/pro.theme.css` 經 `?raw` 交給 Tailwind browser CDN，避免 Vite 把 `@theme`、`@apply` 當成原生 CSS 壓縮。
- 原首頁沒有引入 Tailwind。表單端點、試算表欄位與 Apps Script 保持既有配置。

## 缺口與下次入口

1. 要回答「差距是否擴大」，仍需同定義的跨年資料與家庭組成分析。
2. 應再邀請一般觀眾試看，觀察是否理解比較目的，而非只用內部操作檢查推定可用性。
3. 若希望蒐集「不想選特定主題」的評分，需與 Apps Script 欄位驗證一起調整。本次保留既有三個主題。
4. 回饋寫入已由使用者確認，本次只檢查介面，沒有重新提交測試資料或聲稱完成所有網路故障情境測試。
